# Подготовка исходного шаблона «Северстали», версия 2.0

Источником служат только 15 PPTX из `resources/severstal/templates`. У каждого файла свой `layout_id`; каждый его слайд становится вариантом `slide_001`, `slide_002` и далее. Всего 15 типов и 211 вариантов. Таблица соответствий приведена в README.

## Хранение дизайна

`templates/severstal_template.json` — каталог типов и вариантов. Для каждого варианта записаны исходный файл, номер слайда, нативная часть PPTX, SHA-256 исходной разметки, ссылка на превью и доступные поля. Поле привязано к исходному `shape_id` в слое `slide`, `layout` или `master`.

`templates/severstal_designs/<layout_id>.json` хранит полный исходный DrawingML используемых слайдов, макетов и мастеров. В `parts` общая часть записывается один раз; `variants` содержит ссылки на три слоя. В описании объектов есть имена, идентификаторы, порядок и исходные трансформации в EMU. Шрифты, размеры, отступы, заливки, линии, эффекты и контуры находятся в оригинальной разметке.

`templates/severstal_source.pptx` содержит всю цепочку зависимостей: slide → layout → master → theme, включая изображения, SVG, нативные таблицы/диаграммы, стили и встроенные XLSX/OLE. Унаследованная графика макетов и мастеров переносится вместе со слайдами. Слайды не растрируются.

При объединении служебные ID мастеров/макетов становятся глобально уникальными. PowerPoint требует один notesMaster: ссылки на него нормализуются. Эти изменения не затрагивают фигуры и оформление слайда. XML слайдов и макетов сохраняется побайтно; аудит сравнивает мастера с исключением служебных `sldLayoutId@id`.

## Контракт заполнения

Презентация содержит `template_version: "2.0"`, `title` и `slides`. Слайд содержит разрешённый `layout_id`, исходный `variant_id`, список `updates`, необязательные `notes` и `source_refs`. При `updates: []` сохраняется исходное содержимое, а служебный шаблон даты `##.##.####` в правом нижнем углу автоматически заменяется датой текущей сборки по Europe/Moscow в формате `ДД.ММ.ГГГГ`. Подстановка действует только на результат сборки: исходные PPTX, их контрольные суммы и каталог дизайна сохраняются.

Одна запись `updates` задаёт `field_id` и ровно одну операцию:

| Операция | Поле | Поведение |
| --- | --- | --- |
| `text` | Текст | Заменяет текст, `\n` разделяет абзацы |
| `paragraphs` | Текст | Задаёт текст исходных абзацев массивом строк |
| `rows` | Таблица | Заменяет текст ячеек без изменения сетки и оформления |
| `photo_id` | Изображение | Берёт PNG/JPEG из фотокаталога, пропорционально заполняет исходную рамку и маску с центральным кадрированием |
| `icon_id` | Иконка/изображение | Вставляет SVG с PNG fallback в исходную геометрию |
| `chart_data` | Поддерживаемая диаграмма | Заменяет категории, ряды и значения вместе со встроенным XLSX |

Примеры операций: `examples/severstal_editable.json`. Поля нельзя переносить между вариантами без проверки manifest: `shape_id` локален для исходной части, структура вариантов различается.

Для всех 207 полей `kind: "picture"` записан `placement`: `fit: "cover"`, `preserve_aspect_ratio: true`, `alignment: "center"`, `frame: "source"`, `preserve_source_mask: true`, исходная рамка в EMU и её физические пропорции. Общая политика находится в `photo_placement_policy`. У 60 фотографий геометрия берётся из соответствующего placeholder макета или мастера. Эти метаданные описывают правило замены и не меняют исходную разметку шаблона.

При `photo_id` генератор рассчитывает новый crop по пропорциям выбранного изображения и физической рамки, учитывая масштаб родительских групп. Фото полностью заполняет рамку с сохранением пропорций; лишняя ширина или высота обрезается симметрично. Исходные положение, размер, поворот, маска и эффекты рамки сохраняются. EXIF-ориентация учитывается при расчёте; поворот и отражение при необходимости применяются к отдельной встраиваемой копии. Исходные файлы фотокаталога не изменяются. При отсутствии замены сохраняются исходные изображение и кадрирование.

У всех полей `kind: "icon"` есть `placement`: `slot_shape: "square"`, `fit: "contain"`, `alignment: "center"`, сохранение пропорций, исходная область и квадрат в EMU. При вставке через `icon_id` это правило применяется также к обычному полю изображения. Центр берётся из исходника, сторона квадрата — меньшая физическая сторона исходной области. Для вложенных групп учитываются масштабирование и ориентация родителей: квадрат на слайде может иметь неодинаковые локальные ширину и высоту в координатах растянутой группы.

Результат — невидимая квадратная `p:grpSp` с отдельной `p:pic`, вписанной по большей стороне исходного холста SVG/PNG. Отступы прозрачны, исходный crop/маска/эффекты прежней картинки к новой иконке не переносятся. SVG сохраняется векторным вместе с PNG fallback; оба изображения используют одну геометрию. Исходные прозрачные поля SVG/PNG сохраняются. Объекты блокируют изменение пропорций при ручном масштабировании.

Проверочный пример `examples/severstal_icon_fit.json` показывает широкие, высокие и квадратные ресурсы, а также вложенные группы. В текущих 15 источниках все 1723 вхождения мест разрешаются без ошибок. Для будущего нестандартного поворота внутри неравномерно растянутой группы, создающего сдвиг осей, выдаётся явная ошибка геометрии вместо искажения изображения.

Текстовые стили runs и абзацев сохраняются. Новый текст распределяется по существующим runs; отсутствующие абзацы очищаются. Дополнительные абзацы и превышение `max_characters` отклоняются. Шрифт не уменьшается автоматически. Лимит символов основан на исходном образце и не заменяет проверку переносов. Для новой формулировки выделение разных runs распределяется по исходной пропорции, поэтому смысловые акценты нужно проверить в PowerPoint.

Для модели вычисляется `text_budget`: жёсткий предел, целевая длина около 85% предела, число абзацев и рекомендуемые длины/роли каждого абзаца. Заголовок и основной текст с разными стилями генерируются отдельными элементами `paragraphs`. Пробелы и пунктуация входят в длину, разделители абзацев не учитываются. Например, для `bullets/slide_012/slide_text_22` предел равен 224, цель — 190, ориентиры заголовка/основного текста — 12/176. Для `slide_text_27` это 116, 98 и 9/87 соответственно.

Планировщик видит вместимость варианта до написания текста. Схема текущей порции содержит реальные `field_id` и `maxLength`. Программа собирает все переполнения порции и запрашивает смысловое сокращение только этих полей, передавая текущую длину, предел и цель. Внутренний ответ `field_repairs` программно подставляется в предыдущую структуру; корректные поля, заметки и ссылки на источники сохраняются. `field_repairs` не является форматом готовой презентации. Окончательный файл по-прежнему использует обычные `slides` и `updates`.

Таблица сохраняет исходные число строк/столбцов, объединения ячеек и количество абзацев внутри ячейки. Содержимое скрытых объединённых ячеек не становится видимым.

`chart_data` содержит `categories: [str]` и `series: [{name: str, values: [number]}]`. Размеры должны совпадать с исходными `chart.category_count` и `chart.series_count`. Поддержаны 78 исходных классических диаграмм. Меняются только названия/категории/значения; сохраняются оси, легенды, plots, стили точек, числовые форматы, подписи и остальное оформление. 11 классических диаграмм с нестандартными подписями/неполными кэшами и один chartEx перенесены нативно, но заполняются в PowerPoint. Причины ограничений приведены в manifest.

Для повторных экземпляров варианта создаются отдельные slide и изменяемые chart/workbook/media связи. Неизменённые макеты и мастера используются совместно, как в источнике; при правке унаследованного поля создаётся отдельная цепочка layout/master. Правка одного экземпляра не изменяет другой. Заметки и `source_refs` сохраняются в notes соответствующего экземпляра.

## Каталоги ресурсов

`assets/photos/severstal/catalog.json` содержит 99 фотографий. Дедупликация выполнена по байтам, без перекодирования и потери разрешения. Разные исходные кадры и разрешения сохранены отдельно. Два JPEG XR лежат в `originals`; для вставки доступны связанные PNG. В `usages` указаны все места использования, в том числе макеты и мастера.

`assets/icons/severstal/catalog.json` содержит 30 исходных тематических групп на 33 страницах. Продолжения групп «Продукция», «Безопасность труда» и «Навигация» объединены с сохранением страниц. У каждого исполнения есть `id`, русское имя, семантическое имя файла, описание, теги, группа, SVG/PNG, исходные shape IDs и геометрия. Из 1364 записей 1362 доступны для выбора; две красные пометки из источника сохранены с `selectable: false`.

В библиотеке 1323 векторных SVG и 41 SVG с исходным растром внутри. 576 SVG скопированы из источника побайтно. Другие построены из исходных DrawingML paths; фрагменты одной исходной пиктограммы объединены по её ячейке. Новые пиктограммы не генерировались. Белые исходные изображения сохраняются белыми и показаны на контрастном фоне в контактных листах.

## Воспроизводимость

Из корня проекта, с установленными зависимостями и `PYTHONPATH=src`:

```powershell
python scripts/prepare_severstal_template.py
python scripts/extract_severstal_photos.py
python scripts/extract_severstal_icons.py --render
python scripts/audit_severstal_template.py
python -m unittest discover -s tests
```

Для SVG → PNG при извлечении иконок нужен `resvg_py`; генератору с готовой библиотекой он не нужен. Метаданные фотографий и имена иконок вынесены в `scripts/data/severstal_photo_metadata.json` и `scripts/data/severstal_icon_names*.json`. Неизвестный изменённый фото-исходник требует новой классификации.

Подготовленные шаблоны, каталоги и изображения остаются в `templates/` и `assets/` как ресурсы приложения под контролем Git. Контактные листы фотографий и отчёт извлечения записываются в `output/assets/photos/severstal/`, листы иконок и `source_inventory.json` — в `output/assets/icons/severstal/`. В фотокаталоге `contact_sheets` содержит пути от корня проекта. Оба скрипта извлечения поддерживают `--diagnostics-output` для изменения папки диагностики; у фото `--output` задаёт папку самой библиотеки. Диагностика не нужна для сборки PPTX.

Экспорт исходников: `scripts/export_severstal_sources.ps1 -Root <корень проекта>`. Проверка результата: `scripts/verify_powerpoint.ps1 -InputFile <PPTX> -OutputDirectory <папка>`. Оба скрипта используют установленный PowerPoint через COM и открывают собственную презентацию без окна. Действующие пользовательские презентации не закрываются.

Аудит пишет `output/severstal-audit.json`: число типов/вариантов, исходные байты слайдов, макетов и зависимостей, master artwork, общие темы/стили, внутренние связи OPC, служебные ID и notesMaster, полнота групп иконок, SHA-256 ресурсов и происхождение фотографий. JSON validation и текстовые лимиты не заменяют визуальную проверку нового содержания в целевой версии PowerPoint.

Прежняя подготовка версии 1.x описана в `docs/legacy/template-preparation.md`. Она не определяет разрешённые типы нового шаблона.
