# SuperSlide

Локальная генерация редактируемых презентаций PowerPoint в оформлении «Северстали». Активный шаблон **2.0** подготовлен из **15 файлов в `resources/severstal/templates`**. В нём ровно **15 типов слайдов и 211 исходных вариантов**. Новые типы и композиции не добавлялись.

Модель выбирает существующий тип и вариант, затем заполняет его поля. Дизайн хранится исходными объектами PowerPoint: фигурами, группами, текстом, макетами, мастерами, темами, таблицами и диаграммами. Геометрия, контуры и порядок объектов сохраняются. Каждый заменённый абзац получает единый исходный стиль основного текста: гарнитуру, размер и цвет. Части нового слова не наследуют оформление разных фрагментов образца, например крупного «XX» перед подписью или имени докладчика после названия раздела. Разные абзацы заголовка и основного текста сохраняют своё оформление. В итоговом PPTX заголовки и подзаголовки полужирные, основной текст — обычный: частичное жирное выделение из исходного образца не переносится на новый текст. Новое фото заполняет исходную рамку с сохранением пропорций и центральным кадрированием.

## Структура репозитория

| Папка | Назначение |
| --- | --- |
| `src/superslide/` | Python-пакет: CLI, генератор, локальный веб-сервер и `static/` с интерфейсом |
| `resources/severstal/` | Исходный брендбук и PPTX; 15 активных исходников находятся в `templates/` внутри этой папки |
| `templates/` | Подготовленный активный шаблон, manifest и исходный DrawingML |
| `assets/` | Ресурсы для сборки: фотографии, SVG/PNG и их семантические каталоги |
| `examples/`, `schemas/` | Примеры входных данных и JSON Schema |
| `config/` | Пример настройки LLM и игнорируемая локальная конфигурация |
| `scripts/` | Подготовка, извлечение ресурсов, аудит и экспорт через PowerPoint |
| `scripts/data/` | Проверенные метаданные фотографий и названия иконок для повторного извлечения |
| `tests/` | Автоматические проверки; временные данные создаются в `output/tests/` |
| `docs/` | Описание подготовки шаблона; документация версии 1.x находится в `docs/legacy/` |
| `output/` | Все результаты запусков, отчёты, превью и временные файлы; папка исключена из Git |

Файлы версии 1.x собраны в `templates/legacy/`, `examples/legacy/` и `scripts/legacy/`. Корневые `run.ps1`, `run-web.ps1` и `start-web.cmd` — точки входа для Windows.

Подготовленные шаблоны и каталоги в `templates/` и `assets/` хранятся в Git: они нужны для работы приложения после клонирования. Скрипты подготовки намеренно обновляют эти ресурсы. Контактные листы, диагностические отчёты и экспортированные презентации хранятся отдельно в `output/`.

## Запуск

Нужен Python 3.11+ с зависимостями проекта. `run.ps1` использует `.venv`, `SUPERSLIDE_PYTHON` или Python из среды Codex. Самостоятельная установка:

Для получения больших PPTX нужен Git LFS. Установите его и выполните `git lfs install`, затем после клонирования — `git lfs pull`. В LFS хранятся исходная библиотека `resources/severstal/severstal-template-v29.pptx` и активный шаблон `templates/severstal_source.pptx`.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
```

Из корня проекта:

```powershell
.\run.ps1 inspect-template
.\run.ps1 validate examples/severstal_15_types.json
.\run.ps1 build examples/severstal_15_types.json
.\run.ps1 build examples/severstal_editable.json --output output/severstal_editable.pptx
.\run.ps1 build examples/severstal_all_variants.json --output output/severstal_all_variants.pptx
```

Эти команды используют подготовленный JSON без обращения к модели. CLI и веб-интерфейс по умолчанию работают с новым шаблоном. Веб-интерфейс запускается через `run-web.ps1` или:

```powershell
.\run.ps1 serve --host 127.0.0.1 --port 8765 --open
```

Двойной щелчок по `start-web.cmd` также запускает интерфейс. Если `--output` не указан, `build` пишет `output/<имя входного JSON>.pptx` и соседний `.report.json`, `extract` — `output/sources.json`, а `draft` — `output/draft.json` с сопутствующими файлами источников и диагностики. Эти пути отсчитываются от корня проекта, независимо от текущего рабочего каталога. Явный `--output` задаёт свой путь; относительный путь отсчитывается от текущего рабочего каталога.

Веб-интерфейс показывает структуру под формой создания. Макет каждого слайда выбирается при генерации структуры. В редакторе можно изменить заголовок, найти фото по названию и тегам или загрузить PNG/JPEG с компьютера. Кнопка «Скачать PPTX» собирает и сразу скачивает презентацию. В полях, объединяющих заголовок и основной текст, редактируется только абзац заголовка; остальной текст и мягкие переносы сохраняются.

При генерации модель придумывает короткое название по задаче и документам. Оно сохраняется в свойствах презентации и используется при скачивании: например, `Шаттловые системы 2D и 3D.pptx`. Кириллица сохраняется, а недопустимые для имени файла символы удаляются или заменяются пробелами.

## Заполнение JSON

Слайд выбирается по `layout_id` и `variant_id`. Содержательные поля заменяются только через `updates`, описанные в manifest. Служебная дата в правом нижнем углу вместо `##.##.####` заполняется автоматически текущей датой на момент каждой сборки по часовому поясу Europe/Moscow, в формате `ДД.ММ.ГГГГ`. Исходные PPTX и каталог дизайна сохраняются без этой подстановки.

```json
{
  "template_version": "2.0",
  "title": "Результаты команды",
  "slides": [{
    "layout_id": "title",
    "variant_id": "slide_003",
    "updates": [{"field_id": "slide_text_11", "text": "Результаты команды"}]
  }]
}
```

Поддерживаются `text` или `paragraphs` для текста, `rows` для таблиц, `photo_id` и `icon_id` для изображений, `chart_data` для поддерживаемых диаграмм. Сетка таблицы, число рядов/категорий диаграммы и структура абзацев сохраняются. Шрифт и геометрия не подгоняются автоматически: текст нужно сокращать под исходный вариант. Лимит символов — предварительное ограничение по исходному образцу, а не гарантия отсутствия переполнений для любого текста.

Модель заранее получает `text_budget` каждого поля: жёсткий максимум, целевой объём около 85% максимума и ориентиры по отдельным абзацам. Для заголовка и основного текста с разным оформлением задаются отдельные роли и целевые длины. Пробелы и пунктуация считаются, разделители абзацев не учитываются. Программа проверяет длины сама и передаёт все переполнения одной порции вместе: например, из 284 символов нужно получить около 190 при пределе 224. Исправление не должно обрезать строку или менять подтверждённые числа и единицы.

78 классических диаграмм можно заполнять через JSON с сохранением оформления и синхронной заменой встроенного XLSX. 11 исходных классических диаграмм с особыми подписями/кэшами и объект chartEx сохраняются нативно и редактируются в PowerPoint. Причины ограничений записаны в manifest. Подробности переноса описаны в [инструкции](docs/template-preparation.md).

## Фото и иконки для модели

Фото выбирается по `id`, `name`, `description`, `tags` из `assets/photos/severstal/catalog.json`. Исходные PNG/JPEG сохранены без перекодирования. Два встроенных JPEG XR дополнительно лежат в `originals`; для вставки предусмотрены соответствующие PNG. Повторные использования одного файла перечислены в `usages`.

Для `photo_id` действует единое правило: **заполнение исходной рамки (`cover`) → сохранение пропорций → центральное кадрирование**. Генератор пересчитывает crop для выбранного фото: лишние края обрезаются поровну с противоположных сторон. Положение, размер, поворот и маска исходной рамки, включая круги и произвольные контуры, сохраняются. EXIF-поворот и отражение учитываются; при необходимости нормализуется только встраиваемая копия, файлы фотокаталога остаются неизменными. Правило записано в `photo_placement_policy`, а геометрия — в `placement` каждого поля `kind: "picture"` активного JSON-шаблона, включая рамки, унаследованные от макета.

Каталог иконок — `assets/icons/severstal/catalog.json`: 30 исходных тематических групп, все 33 страницы происхождения, **1362 доступных исполнения**. Ещё две красные пометки «6» и «7» из исходника сохранены с `selectable: false`. У каждого элемента есть семантическое имя, группа, теги, SVG и PNG. 1323 SVG векторные; 41 содержит исходное растровое изображение. 576 SVG скопированы из оригинала побайтно; остальные собраны из исходных контуров DrawingML и изображений.

Иконки разделены по `background_style`: `with_background` (с фоном) и `without_background` (без фона); `has_background` дублирует признак логическим значением. Внутри одного слайда все выбранные иконки должны иметь один тип фона, независимо от тематической группы. Проверка учитывает и оставшиеся исходные иконки при частичной замене; для смены типа нужно заменить все иконки слайда. Модель получает это правило и оба типа в подборке ресурсов. Проверка применяется при генерации, в редакторе, CLI и перед сборкой PPTX: смешение возвращается на исправление. Между слайдами тип может различаться. Исходные справочные страницы библиотеки без замены иконок сохраняются как есть.

Для вставки иконок действует единое правило: **квадратная область → пропорциональное вписывание (`contain`) → центрирование**. Квадрат вписан в исходное место с сохранением его центра; широкая иконка заполняет ширину, высокая — высоту. Размер считается по меньшей стороне исходной области, чтобы не заходить на соседний текст. Масштаб родительских групп компенсируется. В PowerPoint это невидимая квадратная группа с отдельным объектом SVG/PNG внутри и блокировкой изменения пропорций; прежнее кадрирование к иконке не применяется. Модель задаёт только `icon_id`, геометрию определяет генератор.

Политика и геометрия мест записаны в `icon_placement_policy` и `fields.*.placement` активного JSON-шаблона. Проверочный пример: [examples/severstal_icon_fit.json](examples/severstal_icon_fit.json). Его можно собрать командой `.\run.ps1 build examples/severstal_icon_fit.json`, затем экспортировать через `scripts/verify_powerpoint.ps1`.

Для большого каталога модель сначала выбирает исходные варианты и группы иконок, затем заполняет презентацию порциями по одному-два слайда. В каждый запрос попадают только поля текущей порции и подходящие ресурсы. Лимит ответа рассчитывается по объёму полей. При ошибке исправляется только текущая порция; готовые слайды сохраняются отдельно. Положение и стиль объектов модель не задаёт.

При планировании модель считает фактические пункты и получает сведения о составе всех 211 исходных вариантов. Учитываются основные блоки, вложенные группы, маркированные абзацы, таблицы и диаграммы. Для составных слайдов эти количества описываются отдельно: например, три ряда могут содержать 3, 2 и 1 карточку. Если есть подходящий вариант того же типа, несовпадающее число смысловых блоков отправляется на исправление плана. Генерируемые слайды проверяются на незаполненные нумерованные группы и явные образцы вроде `Lorem ipsum` и `Название #3`; программа запрашивает исправление и не добавляет вымышленные факты. Если исправление не удалось, генерация завершается с ошибкой. Ручной JSON и демонстрации исходных вариантов можно собирать без этой проверки.

## Генерация через модель

Рабочая локальная конфигурация хранится в `config/llm.local.json`, пример — `config/llm.example.json`. API-ключ задаётся переменной окружения, указанной в `api_key_env`. Сервис должен поддерживать `chat/completions`.

```powershell
.\run.ps1 draft --task-file examples/task.txt --documents examples/source.txt --config config/llm.local.json --output output/severstal-draft.json --sources-output output/severstal-sources.json
.\run.ps1 build output/severstal-draft.json --sources output/severstal-sources.json --output output/severstal-generated.pptx
```

В интерфейсе «Подключение → Проверить подключение» отправляется отдельный короткий запрос к выбранной модели, без каталога шаблона и документов. Проверка работает отдельно от очереди сборки презентаций. Во время генерации интерфейс показывает этап, номера слайдов и прошедшее время. При тайм-ауте сохраняется информация об этапе; при ошибке структуры — безопасные сведения о поле и ограничении. Файл `output/web/jobs/<id>/diagnostics.json` не содержит ключа, исходного ответа модели и текста документов. Если несколько слайдов уже готовы, их можно скачать как `partial-draft.json`.

Живой API ранее проверен простым тестом доступа; новое разбиение на порции и обработка ошибок проверены автоматическими тестами с подменёнными ответами API. Скорость ответа также зависит от загрузки сервера LLM. Ключ хранится только в памяти: после остановки веб-сервера его нужно ввести заново.

## Воспроизводимость и проверка

При запуске Python напрямую используйте окружение с установленными зависимостями. Из корня проекта в PowerShell задайте `$env:PYTHONPATH = (Join-Path $PWD 'src')`. Подготовка и аудит:

```powershell
python scripts/prepare_severstal_template.py
python scripts/extract_severstal_photos.py
python scripts/extract_severstal_icons.py --render
python scripts/audit_severstal_template.py
python -m unittest discover -s tests
```

Для проверки редактирования заголовков и скачивания файлов в веб-редакторе нужен Node.js; дополнительные пакеты не требуются: `node --test tests/frontend/*.test.cjs`.

Для генерации PNG иконок нужен дополнительный `resvg_py` (`python -m pip install resvg_py`); вставка уже подготовленной библиотеки его не требует. Для экспорта превью и PDF нужен установленный Microsoft PowerPoint: `scripts/export_severstal_sources.ps1` и `scripts/verify_powerpoint.ps1`.

| Путь | Содержимое |
| --- | --- |
| `output/assets/photos/severstal/` | Фотоконтактные листы и `extraction_report.json` |
| `output/assets/icons/severstal/` | `contact_sheets/` и `source_inventory.json` |

Структурный аудит и автоматические тесты не заменяют просмотр оформления и переполнений нового содержания. Особенности и пометки исходного шаблона сохраняются.

Её файлы `templates/legacy/corporate_base.pptx` и `templates/legacy/template_manifest.json` оставлены для явного открытия старых JSON через `--template` и `--manifest`. Они не входят в активный каталог 15 типов.
